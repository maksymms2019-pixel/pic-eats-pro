# План: точність — головний пріоритет

Зараз AI часто помиляється з продуктами та калоріями, а норма рахується за спрощеною формулою. Виправляємо у двох напрямках: **(1) точніший аналіз фото з підказками користувача та кращою моделлю**, **(2) точніший розрахунок денної норми з ширшим набором параметрів**.

---

## 1. Точність розпізнавання їжі по фото

### 1a. Кращий промпт + перехід на сильнішу модель
- Замінити `google/gemini-2.5-flash` на `google/gemini-2.5-pro` в `src/routes/api/analyze-food.ts` — pro значно точніший на vision-задачах з оцінкою порцій.
- Переписати системний промпт: змусити модель спочатку **перелічити видимі компоненти** (chain-of-thought всередині tool call), оцінювати вагу кожного компонента окремо, використовувати референси розміру (тарілка ~26см, виделка ~20см), і лише потім сумувати макроси.
- Розширити схему tool call:
  - `items`: масив компонентів `{ name, grams, calories, protein_g, carbs_g, fat_g }`
  - `assumptions`: що саме AI припустив (тип олії, спосіб приготування, додані соуси)
  - `needs_clarification`: boolean — чи варто уточнити у користувача
  - `clarification_question`: конкретне питання (напр. "Це смажено на олії чи на сухій сковорідці?")
  - `confidence` залишається

### 1b. Уточнення від користувача → повторний аналіз
Найважливіше за запитом користувача: можливість сказати AI "це насправді Х" і отримати новий розрахунок.

На екрані `scan.tsx` після першого результату:
- Показувати розпізнані компоненти списком (можна видалити кожен)
- Показувати `assumptions` AI
- Поле **"Уточнити для AI"** з прикладами-плейсхолдерами ("це куряче філе ~150г, гречка ~100г, без олії")
- Кнопка **"Перерахувати"** → новий запит до `/api/analyze-food` з тим же фото + `hint` з уточненням + попередньою відповіддю як контекст. Модель отримує інструкцію довіряти користувачу більше ніж власному визначенню.
- Кнопка **"Це зовсім інша страва"** → користувач вводить назву та вагу, AI рахує макроси по назві (без фото взагалі, через ту ж модель).
- Опційне поле **"вага порції в грамах"** перед збереженням — якщо користувач знає точну вагу, всі макроси пропорційно перераховуються локально (без нового AI-запиту).

### 1c. Контекст для кращої оцінки порції
Додати в запит до AI:
- стать, зріст, вага користувача (для оцінки розміру руки/тарілки на фото, якщо є)
- опційно: дозволити користувачу зробити друге фото "поряд з рукою/виделкою" для масштабу

## 2. Точніший розрахунок денної норми (BMR/TDEE)

Зараз: формула Mifflin-St Jeor + 5 рівнів активності + фіксовані −500/0/+350 ккал і 30/40/30 макроспліт. Замало параметрів.

### 2a. Розширити онбординг
Додати в `onboarding.tsx` та таблицю `profiles`:
- **Метод розрахунку BMR**: Mifflin-St Jeor (за замовч.) АБО Katch-McArdle (точніший, якщо є % жиру)
- **% жиру в тілі** (опц., 5-50%) — вмикає Katch-McArdle: `BMR = 370 + 21.6 × LBM_kg`
- **Окремо тренування** (на додачу до повсякденної активності):
  - тип: силові / кардіо / змішане / немає
  - частота: 0-7 разів на тиждень
  - тривалість: 15-120 хв
  - Додає реалістичні ккал поверх базового множника активності (не подвійний рахунок)
- **Темп зміни ваги** (slider): −1000…+500 ккал/день, з підказками "−0.5 кг/тиждень = −500 ккал" і м'яким попередженням якщо <1500 ккал
- **Цільова вага** + дата → авто-обчислення необхідного дефіциту/профіциту; перевірка що це безпечно (макс 1% маси тіла на тиждень)
- **Макроспліт**: пресети (збалансований / високобілковий / кето / низькожировий) АБО ручне налаштування з валідацією що сума = 100%
- **Білок за вагою** (альтернатива до % від калорій): 1.6-2.2 г/кг для дефіциту/набору м'язів — це точніше за відсотки
- **Корекція за віком**: автоматичний коефіцієнт −2% за кожне десятиліття після 30 (метаболічне сповільнення)

### 2b. Адаптивна корекція по факту
Раз на тиждень в `today.tsx` показувати картку "Перевірка прогресу":
- Якщо вага змінюється швидше/повільніше за ціль протягом 2+ тижнів → пропонувати скоригувати норму на ±100-200 ккал
- Потребує: трекінг ваги (нова таблиця `weight_logs` з полями `weight_kg`, `logged_at`) + поле для запису ваги на головному екрані

### 2c. Прозорість розрахунку
В `profile.tsx` показати breakdown: "BMR 1650 + активність 380 + тренування 250 − дефіцит 500 = 1780 ккал" — щоб користувач бачив звідки число.

## 3. Точність БЖВ в базі продуктів і ручному вводі
- В `foods.tsx` при ручному додаванні — інтеграція з Open Food Facts API (вже згадана раніше) для пошуку по назві з готовими БЖВ на 100г.
- Валідація: якщо БЖВ не б'ється з ккал (4·білки + 4·вуглеводи + 9·жири повинно бути в межах ±15% від ккал) — показати попередження.

## Технічні деталі

**Зміни в БД** (одна міграція):
- `profiles`: додати `body_fat_pct`, `bmr_method`, `workout_type`, `workout_frequency`, `workout_duration_min`, `target_weight_kg`, `target_date`, `macro_preset`, `protein_per_kg`
- нова таблиця `weight_logs` (id, user_id, weight_kg, logged_at, notes) + RLS + GRANT

**Зміни в `src/lib/nutrition.ts`**:
- `computeBMR(method, profile)` — підтримка Mifflin та Katch-McArdle
- `computeActivityCalories(activity, workout)` — окремо повсякденна і тренувальна
- `computeTargets()` з підтримкою кастомного макроспліту і білка за вагою
- `validateMacros()` — перевірка узгодженості ккал/БЖВ

**Зміни в `src/routes/api/analyze-food.ts`**:
- Модель → `gemini-2.5-pro`
- Новий промпт з покроковим аналізом
- Розширена tool схема (`items[]`, `assumptions`, `needs_clarification`, `clarification_question`)
- Підтримка контекстного запиту: приймати попередню відповідь AI + уточнення користувача

**Зміни в `src/routes/scan.tsx`**:
- UI для редагування компонентів, перегляду assumptions
- Поле уточнення + кнопка "Перерахувати"
- Кнопка "Це зовсім інша страва" з ручним вводом назви
- Локальний перерахунок макросів при зміні ваги порції

**Зміни в `src/routes/onboarding.tsx`** та `profile.tsx`:
- Багатокроковий wizard з усіма новими полями
- Можливість змінити будь-який параметр пізніше
- Прозорий breakdown розрахунку

**Зміни в `src/routes/today.tsx`**:
- Поле "Записати вагу" + щотижнева картка корекції

## Що НЕ робимо в цій ітерації
- Push-нагадування зважуватись
- Інтеграцію з Apple Health / Google Fit (вимагає нативного аппа)
- AI-сканування упаковок з calorie label (можна додати окремо пізніше)

Готовий реалізувати — підтверди, і починаю з міграції БД + оновлення нутриційної логіки, далі — UI скану та онбордингу.
