## Фінальне оновлення — на що націлено

Головна ціль — максимальна точність визначення страв і калорій + можливість додавати кілька фото (основне + уточнювальні: пачка, етикетка, інший ракурс, склад). Плюс загальна шліфовка.

---

### 1. Мульти-фото аналіз (головна нова фіча)

**Сканер (`src/routes/scan.tsx`):**
- Замість одного `preview/file` — масив `photos: File[]` (до 4 фото).
- Перше фото — головне (страва), решта — уточнювальні (пачка, етикетка, склад, інший ракурс).
- UI: великий слот головного фото + рядок міні-превʼю з кнопкою "+ ще фото" (камера/галерея). Кожне фото можна видалити (×). Підпис під слотом: "Основне" / "Уточнення".
- Після аналізу всі фото лінкуються до запису: перше йде в `food_entries.photo_url`, всі — в новий масив (див. БД).
- При збереженні в "Мої страви" — також зберігаємо всі фото.

**Сервер (`src/routes/api/analyze-food.ts`):**
- Приймає `imagesBase64: string[]` (бекворд-сумісно з `imageBase64`).
- Передає всі фото в один виклик Gemini як кілька `image_url` партів + системний промпт: "Перше фото — сама страва. Наступні — уточнення (упаковка, етикетка, склад, інший ракурс). ОБОВʼЯЗКОВО використай інформацію з етикеток (бренд, ккал/100г з пачки) як істину в останній інстанції."
- Якщо AI бачить етикетку з ккал/100г — використовує саме ці значення замість оцінки на око.

### 2. Точність AI — ще щільніше

`src/routes/api/analyze-food.ts`:
- **Self-consistency**: два паралельні виклики з різними `seed` (42 і 7), беремо медіану по ккал/Б/Ж/В. Якщо розкид > 25% — піднімаємо `confidence: low` і додаємо `clarification_question`.
- **OCR-пріоритет**: якщо одне з фото — упаковка з читабельною таблицею харчової цінності, AI має витягнути значення з неї та масштабувати під оцінену вагу порції (промпт + приклад в системі).
- **Розширені якорі**: додаю популярні українські страви (борщ ~50 ккал/100г, вареники з картоплею ~180, голубці ~110, сирники ~210, шаурма ~220, піца Маргарита ~250) і базові снеки (чіпси ~530, шоколад молочний ~545, печиво овес ~440).
- **Кращий валідатор**: поточна перевірка енергобалансу залишається, але додам "sanity-чек" на крайні значення (ккал/г > 9.5 або < 0.1 → перерахунок).
- **Контекст від користувача**: окрім топ-20 фаворитів передаю останні 5 записів з щоденника (за тиждень) — допомагає AI впізнавати "ту саму страву".

### 3. UI/UX шліфовка

- **Картки запису в щоденнику (`today.tsx`)**: тап на фото → відкриває фул-скрін перегляд (простий dialog з усіма фото записа, свайп). Додаю кнопку ♥ для збереження запису в фаворити.
- **Меню (`AppLayout.tsx`)**: підпис під камерою (зараз `invisible "."`) робимо "Скан" — щоб не було дірки. Активний стан кнопки камери — лагідне `scale-105`. Дрібний фікс: висоти всіх 6 слотів вирівнюються.
- **Сканер**: коли AI повертає `needs_clarification` — підказка пропонує "Додати уточнювальне фото" як CTA одразу.
- **Прогрес-індикатор**: під час аналізу показує "AI вивчає фото 1/3…" для кожного фото.
- **Фаворити (`foods.tsx`)**: показуємо до 3 мініатюр на карточці (не лише головне фото). Сортування: останні використані вгорі.
- **Сторінка `coach.tsx`**: дрібно — фікс відступу низу під меню (pb-28).
- **Помилки мережі**: уніфікований toast при offline ("Немає інтернету — спробуй ще раз").

### 4. БД — міграція (одна)

```sql
ALTER TABLE public.food_entries
  ADD COLUMN photo_urls text[] DEFAULT '{}'::text[];

ALTER TABLE public.favorites
  ADD COLUMN photo_urls text[] DEFAULT '{}'::text[];
```

`photo_url` залишається для зворотньої сумісності (= перше фото); `photo_urls` — повний список. Старі записи не ламаються.

## Технічні деталі

**Файли під редагування:**
- `src/routes/scan.tsx` — мульти-фото state, UI, аплоад масивом
- `src/routes/api/analyze-food.ts` — приймає масив, self-consistency, OCR-промпт, нові якорі
- `src/routes/today.tsx` — лайтбокс для фото, кнопка ♥
- `src/components/AppLayout.tsx` — підпис "Скан", вирівнювання
- `src/routes/foods.tsx` — кілька мініатюр
- `src/routes/coach.tsx` — pb-28 фікс
- 1 міграція БД

**Не чіпаю:** онбординг, профіль, формули BMR/TDEE, auth — стабільні.

**Бюджет AI:** self-consistency = 2× запитів на аналіз. Для тарифу Lovable AI це прийнятно; вмикаю тільки для головного аналізу (не для "перерахуй з підказкою").
